# Описание к уточненной диаграмме AS-IS

Уточненная диаграмма вскрывает:

1. Прямые SQL-вызовы из монолита в Oracle.  
   Критическая связность: 5 из 6 компонентов монолита напрямую работают с Oracle:
   - **Pricing & Promo Logic** — правила, коэффициенты, legacy promo logic
   - **Order Processing** — заказ, резерв, служебные таблицы
   - **Status Management** — статусы, история, технические состояния
   - **Payment Orchestration** — payment_session_id, технические атрибуты
   - **Delivery Routing** — правила маршрутизации, партнёры, retry-состояния

2. Синхронные вызовы наружу.  
   Длинные транзакции в критичном контуре приводят деградация на пиках:
   - **Payment Orchestration** — **Платёжные провайдеры**
   - **Delivery Routing** — **Службы доставки**

3. Обмен через БД.  
   Системы завязаны на схему таблиц. Изменение приводит к побочным эффектам.
   - **Monolith** — **Oracle** (INSERT в INT_ORDER_EXPORT)
   - **Oracle** — **.NET Integration** (SELECT + обработка)
   - **.NET Integration** — **Oracle** (Запись результата)

4. Аналитика конкурирует с операционным контуром.  
   Аналитика забирает ресурсы операционной БД прямыми запросами, это приводит к деградации
   - **Python Analytics** — **Oracle** (прямые выборки, витрины, долгие отчёты)
   - **BI / отчётность** — **Oracle** (крупные запросы с витринами)

5. Ручные вмешательства встроены в жизненный цикл заказа.

6. Разнородный интеграционный контур, нет единого стандарта интеграции.  
   REST / смешанное резервирование / прямой SQL / очереди / batch
