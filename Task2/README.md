# Анализ и формирование требований при трансформации легаси

У нас уже есть информация о контексте, которую можно проанализировать. Есть диаграмма AS-IS, которую кроме всего прочего надо провалидировать. Есть также интервью с несколькими разработчиками из разных команд. А также есть кусок кода из Java-монолита. Это всё можно проанализировать и выявить что есть сейчас, карту текущего состояния системы со всеми зависимости архитектурными дефектами и ограничениями, т.е. выявить **что у нас сейчас есть**.

Работу по заданию выстроим в несколько шагов:

1. Проанализируем три стенограммы интервью с разработчиками:
   - [Java Tech Lead команды заказов и оформления](./sources/interview-1-tech-lead.md)
   - [Senior Developer команды логистики и внешних интеграций](./sources/interview-2-logistics.md)
   - [Senior Python Developer команды аналитики и отчётности](./sources/interview-3-analytics.md)
2. Проанализируем [фрагмент кода](./sources/OrderProcessingService.java) из Java-монолита
3. Подготовим документ [анализа текущего состояния системы](./as-is-analysis.md)
4. Подготовим [AS-IS диаграмму контекста](./as-is.drawio), актуальную, верифицированную
5. Сформируем канву [Software Architecture Canvas](./architecture-canvas.md), плакат с выжимками по текущей архитектуре
