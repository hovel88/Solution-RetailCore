# Анализ и формирование требований при трансформации легаси

У нас уже есть описание текущего состояния архитектуры, а также проведен анализ этого состояния. Нам теперь нужно определить целевую архитектуру и поэтапный план трансформации, чтобы максимально безопасно и комфортно перейти от AS-IS к TO-BE.

Работу по заданию выстроим в несколько шагов:

1. Подготовим [TO-BE диаграмму контекста](./to-be.drawio), где покажем целевые границы системы, основные подсистемы, новые или изменённые интеграции, участки, которые сохранятся без изменений и которые будут изменены в первую очередь.
2. Составим [файл с описанием трансформации](./transformation.md). Там опишем целевую архитектуру, этапы трансформации, какие проблемы решаются, какими метриками проверяются изменения, сформируем список и описание точек трансформации.
