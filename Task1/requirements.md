# Требования к трансформации — RetailCore

RetailCore — розничный ретейлер с собственной платформой управления заказами, логистикой и партнёрскими интеграциями. Платформа развивалась эволюционно, без единого архитектурного замысла. В результате имеем:

- монолитное ядро на Java + Oracle
- вспомогательные сервисы на .NET
- аналитика на Python
- обмен данными через общую БД, API и очереди
- on-premise инфраструктура на пределе ресурсов.

Бизнес требует трансформации платформы: повышения скорости изменений, устойчивости критичного контура, наблюдаемости и подготовки к новым сервисам.

Источники исходных данных:

- [Описание кейса](../CONTEXT.md) — контекст, бизнес-цели, ограничения
- PlantUML-диаграмма [AS-IS](../AS-IS.puml) — текущий ландшафт (неполная, требует валидации)
- Стенограмма интервью с [Дмитрием](./sources/interview-business.md) — бизнес-цели, ограничения, принципы
- Стенограмма интервью с [Ольгой](./sources/interview-support.md) — проблемы поддержки, наблюдаемость, Unhappy Path

Все требования классифицированы по типам:

- **FR** — функциональные требования
- **NFR** — нефункциональные (архитектурно значимые)
- **GAP** — пробелы в данных
- **CON** — ограничения
- **ASM** — допущения
- **RISK** — риски
- **PRIN** — принципы работы

> По постановке задания есть важное правило: если данных нет, то это GAP, никаких выдуманных значений.
